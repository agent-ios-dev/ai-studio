# Ai Studio — бесплатная бета

Сайт для GitHub Pages и отдельный Cloudflare Worker. GPT-6 Luna вызывается через нативный OpenAI Responses API, Gemini 3.8 Flash — через нативный Gemini API. Регистрация и оплата отсутствуют: у каждого пользователя личная секретная ссылка.

## Возможности

- Диалоги и контекст сохраняются в D1 и доступны на разных устройствах по личной ссылке.
- Файлы до 3 штук по 5 МБ сохраняются в приватном Workers KV, доступны только владельцу ссылки и удаляются вместе с чатом. Модель получает сам файл при отправке. В следующих сообщениях Worker повторно добавит последний файл в контекст, а если в вопросе названо имя файла — выберет файл по имени.
- Можно выбрать модель и глубину размышления. В настройках задаётся модель по умолчанию.
- Для GPT-6 Luna можно включать поиск в интернете прямо в поле ввода. Gemini пока не поддерживает этот переключатель. Когда поиск включён, Worker добавляет `web_search` к запросу OpenAI, а источники ответа сохраняются вместе с чатом и показываются ссылками. Поиск может оплачиваться отдельно у OpenAI; дневной лимит сайта учитывает токены.
- Ответы моделей отображаются с форматированием Markdown: заголовками, списками, выделением, кодом, таблицами и ссылками. HTML из ответа не выполняется. Парсер хранится в проекте, поэтому внешний CDN не нужен.
- Профиль содержит имя, текст «О себе» и переключатель памяти. Память ищет подходящие выдержки в сохранённых диалогах и добавляет до трёх в контекст нового запроса.
- Временный чат живёт только в открытой вкладке, не сохраняется в D1 и исчезает после обновления или закрытия страницы. Его запросы входят в дневной лимит.
- Пользователь видит округлённый процент оставшегося дневного лимита. На сервере действует единый лимит 50 000 токенов в сутки для всех моделей. Бесплатные сбросы накапливаются до максимума и позволяют восстановить лимит до конца текущих суток.
- Админка требует личную ссылку администратора и отдельный пароль. В ней можно менять дневной лимит, периодичность и размер начисления сбросов, максимальный запас, выдавать персональные ссылки и добавлять сброс конкретному пользователю.

## Локальный просмотр

```powershell
npm run preview
```

Откройте `http://localhost:4173`. Адрес Worker задан в `config.js`, а для входа нужна личная ссылка. Без неё сайт не создаёт пробные диалоги и не показывает вымышленные ответы.

## Развёртывание Cloudflare Worker

1. Войдите в Cloudflare CLI: `npx wrangler login`.
2. Создайте базу: `npx wrangler d1 create ai-chat`.
3. Создайте KV namespace: `npx wrangler kv namespace create ai-chat-files`.
4. Скопируйте `worker/wrangler.example.toml` в `worker/wrangler.toml`. Впишите `database_id` из шага 2, `id` KV namespace из шага 3 и точный `ALLOWED_ORIGIN` сайта без завершающего `/`. Например, для GitHub Pages проекта origin равен `https://USERNAME.github.io`, даже если путь сайта содержит имя репозитория.
5. Создайте таблицы из корня проекта: `npx wrangler d1 execute ai-chat --remote --file worker/schema.sql`.
6. Из папки `worker` добавьте ключи **только как секреты**: `npx wrangler secret put OPENAI_API_KEY`, затем `npx wrangler secret put GEMINI_API_KEY`. Создайте длинный случайный пароль администратора, сохраните его SHA-256 в секрете `ADMIN_PASSWORD_HASH` через `npx wrangler secret put ADMIN_PASSWORD_HASH`.
7. Из папки `worker` выполните `npx wrangler deploy` и запишите полученный URL Worker.

Ключи моделей нельзя добавлять в `config.js`, GitHub или HTML. Ключи, уже отправленные в чат, лучше перевыпустить перед публичным запуском.

## Развёртывание GitHub Pages

В репозитории есть workflow `.github/workflows/pages.yml`. Он публикует только файлы сайта, не включает код Worker и подставляет адрес API из переменной репозитория `CHAT_API_URL` в `config.js` при каждой публикации. Значение переменной — URL Worker без завершающего `/`, например `https://ai-chat-api.example.workers.dev`.

После загрузки проекта в репозиторий включите GitHub Pages с источником **GitHub Actions**. Workflow запускается при push в `main` или вручную. Для собственного домена задайте его в настройках Pages и измените `ALLOWED_ORIGIN` Worker на новый origin.

## Первая админская ссылка

Из корня проекта выполните:

```powershell
node scripts/create-invite.mjs https://USERNAME.github.io/REPOSITORY/ --admin
```

Скрипт выведет SQL-команду для вставки администратора в D1 и личную ссылку на админку. Выполните SQL через `wrangler d1 execute ai-chat --remote --command "..."`. Для входа нужны эта ссылка и пароль, хеш которого сохранён в `ADMIN_PASSWORD_HASH`. После этого администратор сможет создавать пользовательские ссылки в самой админке.

Личная ссылка содержит токен после `#invite=`. Он не передаётся GitHub Pages при открытии страницы: браузер сохраняет его локально и убирает из адресной строки. Любой, кому станет известна эта ссылка, получит доступ к соответствующим чатам и лимиту. Передавайте её приватно.

## Ограничения

- Модель может прочитать поддерживаемый формат, а не произвольный бинарный файл. Пользователь может выбрать любой файл, но Worker отклонит формат, который выбранная модель не поддерживает. GPT-6 Luna принимает изображения и [поддерживаемые документы](https://developers.openai.com/api/docs/guides/file-inputs); Gemini 3.8 Flash — изображения, PDF, поддерживаемые аудио/видео и текстовые файлы.
- Память ищет по словам из запроса и недавности. Она добавляет до трёх подходящих диалогов, а не весь архив целиком. Отключение памяти исключает другие диалоги из запросов к модели.
- Временный чат не сохраняет файлы в KV, поэтому вложения в нём исчезают вместе со страницей. KV может отдавать новые вложения с задержкой в других регионах из-за распределённой репликации.
- Сутки для лимита считаются по Москве (UTC+3). Учитывается общий расход входа, ответа и рассуждений; стоимость этих токенов различается между моделями. Настройте бюджетные ограничения и мониторинг у провайдеров перед расширением доступа.
- Ответы пока приходят целиком, без потоковой печати.
- GitHub Pages используется для бесплатной беты. [Правила GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits) не допускают коммерческий SaaS на этой площадке.

## Вход через Telegram и личные ссылки

Основной вход — Telegram Login. Запасной — личная ссылка из админки. Telegram создаёт отдельный профиль; переноса личных ссылок пока нет. Повторный вход в тот же Telegram сохраняет историю, персонализацию и лимиты.

В @BotFather выберите бота → Login Widget, добавьте `https://ai-studio-gpt.eu.cc` и `https://ai-studio-gpt.eu.cc/` в Allowed URLs. Оставьте алгоритм RS256. В переменных Worker задайте `TELEGRAM_CLIENT_ID` из этого раздела и `TELEGRAM_AUTH_ENABLED = "true"`. Используется официальный JS SDK и серверная проверка id_token по публичным ключам Telegram; Client Secret и токен бота для этой схемы не нужны. Запрашивается только профиль, без телефона и разрешения писать пользователю.

Для существующей базы из папки worker выполните `npx wrangler d1 execute ai-chat --remote --file ./migrations/004_telegram_auth.sql`, затем deploy. Новая schema.sql уже включает таблицы. Попытка входа действует 10 минут, привязана к одноразовому nonce и секрету браузера; повторное использование блокируется. Сеанс хранится в браузере, в базе — только его хеш, срок 30 дней; выход отзывает сеанс.

Почтовая форма убрана, `EMAIL_AUTH_ENABLED = "false"` отключает выдачу кодов через прежние API. Старые почтовые аккаунты и их активные сеансы сохраняются. Таблицы почтовых кодов и прежние секреты не удаляются.

## Liquid Glass

Панель ввода, меню моделей и диалоговые окна используют компонент из [winaviation/liquid-web](https://github.com/winaviation/liquid-web) под MIT-лицензией. Код и лицензия находятся в `vendor/liquid-web`, адаптация размеров — в `liquid-glass.js`. В Chromium используются карты SVG-преломления и блики; в других движках — предусмотренный автором blur fallback. Режимы reduced transparency и forced colors получают непрозрачные панели. Карты пересчитываются только при изменении размера, текст и элементы управления остаются вне фильтра.

## Проверки приложения

`npm test` проверяет изоляцию личных ссылок, контекст, лимит, сброс, временный чат, память, админские настройки и приватность файлов.

## Закрепление и сводка памяти

Чаты закрепляются кнопкой булавки в боковой панели; закрепления хранятся в D1 и синхронизируются с аккаунтом.

Отдельная «Сводка памяти» доступна из бокового меню и настроек. В обычной переписке модель автоматически формирует и обновляет сводку из явно сообщённых пользователем устойчивых фактов, планов и предпочтений. Обновление возвращается в служебной части того же ответа, удаляется перед показом и сохранением сообщения и не требует отдельного запроса или дополнительного лимита. Служебный блок помечен случайным идентификатором запроса; некорректные блоки не меняют память. При параллельных изменениях более новая сводка не перезаписывается. Временные чаты и выключенная память исключены. В редакторе памяти сообщения вроде «я учу английский» обновляют сводку через нейросеть и не создают обычный диалог. Используется GPT-6 Luna; при ошибке — Gemini с существующими запасными ключами. Расход обновления памяти и распознавания голоса входит в единый токенный лимит. Сводка передаётся моделям только при включённой памяти и никогда — во временных чатах. Удаление обычных чатов не удаляет сводку; для очистки напишите «Очисти всю память». Версия сводки защищает от одновременной перезаписи с нескольких устройств.

Для существующей базы из папки worker выполните `npx wrangler d1 execute ai-chat --remote --file ./migrations/005_pins_memory.sql` перед deploy.

## Единый токенный лимит

Миграция `worker/migrations/006_token_quota.sql` устанавливает 50 000 токенов на пользователя в сутки, сохраняет пользователей, чаты и запас бесплатных сбросов. Старые таблицы счетчиков запросов сохраняются как архив, но больше не ограничивают доступ. Граница суток — 00:00 по Москве; клиент обновляет процент после запроса и в полночь.

Входной контекст, выход и рассуждения учитываются из usage провайдера без двойного учета reasoning/cached tokens. Во время генерации остаток резервируется; параллельные генерации и сбросы блокируются. По завершении неиспользованный резерв возвращается. Если usage отсутствует, успешная генерация учитывается консервативно по верхней оценке входа и разрешенному выходу; для непрозрачных вложений/аудио — по всему резерву. В интерфейсе появляется пометка об оценке. После аварийного завершения Worker просроченный резерв также списывается консервативно.

Выход ограничен доступным бюджетом и консервативной оценкой текстового входа. При неизвестной стоимости мультимодального входа либо превышении провайдером запрошенного ограничения фактический расход одного запроса может превысить остаток; он сохраняется полностью, остаток отображается как 0%. Бесплатный сброс восстанавливает общий токенный баланс текущих суток. Размер дневного лимита можно менять в админке.

## Голосовой режим

Кнопка со звуковой волной, боковое меню или Gemini 3.8 Live в списке Google открывают полноэкранный разговор по пользовательскому SVG. Круг анимируется и реагирует на громкость микрофона/ответа; учитывается reduced motion. Микрофон справа выключает передачу звука, крестик завершает разговор. Микрофон освобождается при выходе, уходе в другую вкладку или ошибке. Старый микрофон в поле ввода сохраняет режим диктовки с текстовым ответом.

Worker проксирует WebSocket Google: долгоживущие API-ключи не передаются браузеру. Одноразовый билет на подключение действует минуту. Один сеанс длится до пяти минут и заканчивается перед полуночью по Москве; затем можно начать следующий. Токены резервируются из существующего дневного баланса, расход берётся только из серверных сообщений Google по завершённым ходам. Незавершённое аудио при разрыве оценивается консервативно (показывается как оценённый расход). При исчерпании бюджета сеанс завершается. Никогда не доверяем числам usage, присланным клиентом.

Расшифровка сохраняется как отдельный голосовой чат; его можно продолжить кнопкой голоса. Передаются персонализация и существующая сводка памяти; автоматическое обновление сводки по-прежнему выполняется в текстовых чатах. Служебная копия контекста удаляется при закрытии голосовой сессии. Для развёртывания нужна миграция `worker/migrations/007_live_voice.sql`, затем Worker и Pages.
